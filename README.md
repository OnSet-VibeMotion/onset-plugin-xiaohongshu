# 片场 · 小红书上传助手

选一个小红书账号，插件在**片场客户端内**自动上传视频、封面并填入文案，随后由你在同一个小红书页面检查和点击发布。支持多个账号，登录状态在本机独立保存，账号可跨项目使用。

## 在片场中安装

需要带有 `browser` 内嵌网页插件接口的片场客户端。0.2.0 插件需要配套的客户端更新；旧客户端会拒绝未知清单字段或提示更新。用户不需要安装 Chrome、Edge、Node、Python 或 npm。

打开片场「设置 → 我的插件」，添加来源：

```text
github:OnSet-VibeMotion/onset-plugin-xiaohongshu#main
```

检查说明后点「装上」。私有仓库需要本机 Git 已有读取权限。本地开发可添加 `link:/本机绝对路径/onset-plugin-xiaohongshu`。仓库包含 `dist/plugin.cjs`，安装和上传时不编译、不下载运行依赖。

## 使用

1. 在片场完成视频和发布信息（`publish.md`）。主平台是不是小红书都可以：标题优先用 `copy.platform_titles.xiaohongshu`（没有就用主标题，小红书标题最多 20 字）；封面依次挑小红书的 3:4、小红书的其他比例、任何平台的 3:4、任何一张，没有登记封面就用视频首帧。
2. 点「登录新账号」（发布页里的小红书窗口，或片场设置 → 功能与插件 → 小红书上传助手 →「详情与设置」里的「登录小红书账号」）。片场会弹出小红书页面，在里面扫码或用手机号登录；登录好后插件自动记下昵称与头像，页面自动关掉、回到片场。点顶部「返回片场」或十分钟没登录，就当这次不登，不会留下半截的账号。
3. 可以继续登录别的账号。同一个小红书账号再登录一次，会换掉旧的那条。设置里每个账号的卡片上有「打开」「移除」；移除会一并删掉它的登录状态。
4. 选择账号，点「上传并填写」并确认执行。插件在客户端内上传视频与封面，填入标题、正文、话题和必要的素材署名。
5. 自动填写结束后，检查实际登录账号、封面和文案，按需修改，最后由你点击小红书的「发布」。

「打开小红书」会回到所选账号已有的页面，保留你填写中的内容；不存在页面时打开创作者后台。顶部「返回片场」只隐藏页面。关闭片场会关闭页面，登录状态保留，但网站未保存的编辑内容不保证保留。

昵称与头像是登录后从小红书页面读到的：先问创作者中心的接口，读不到再从页面上的头像与昵称认。小红书改版后如果认不出来，登录会一直等到十分钟超时，请把情况反馈给插件作者。

## 内容与状态

- 本版处理**视频笔记**，读取 `publish.md` 的 `video.path`、`copy.primary_title`、`copy.introduction`、`copy.hashtags`、`credits` 与 `cover.images`。优先使用小红书的 3:4 封面；候选不明确时停止。
- 有成片 SHA-256 时先校验。文件真实路径必须位于项目内，拒绝符号链接指向项目外的素材。
- 话题匹配不到联想项时保留 `#话题` 文字并提醒检查。封面失败时报告失败，保留内嵌页面。
- `ready_to_publish` 只表示填表完成，**不表示发布成功**。插件没有自动发布、定时提交、后台批量发布或提交重试功能。
- 再点「上传并填写」会重新准备编辑页，可能覆盖这个账号尚未发布的编辑内容。只想继续检查时使用「打开小红书」。
- 同一个成片上次已经传过、还没发布时不会重新上传：小红书离开编辑页时会把它存成这个账号浏览器里的本机草稿（草稿箱里写着「草稿存储于当前使用的浏览器本地」），视频已经在小红书那边。插件按视频文件大小在本机草稿库（IndexedDB `draft-database-v1`）里认出那条草稿，从草稿箱点「编辑」接着填标题、正文、话题和封面。成片重新渲染过（大小变了）或认不出草稿时照常上传。
- 话题逐字输入后从小红书的候选里按话题名选中，并核对正文里确实变成了话题；小红书没有这个话题时保留为文字并提醒。
- 登录失效时在内嵌页面重新登录，或在设置里移除后重新登录；如果网站把页面带回首页，点「返回片场」后重新准备。

## 数据存放

```text
<插件私有 data_dir>/
  accounts/<账号编号>/account.json    # 昵称、头像与小红书用户编号
  accounts/<账号编号>/browser/        # 操作锁，兼容原有账号目录
  web-sessions/<账号编号>/            # 旧版的登录空间，移除账号时删掉；现在登录状态由片场存在它自己的应用数据目录里
```

登录凭据不进入项目和 Git 仓库。项目内 `production/xiaohongshu/` 只有账号的昵称与头像、进度及准备状态。每次操作的网页控制连接由片场签发，操作结束后撤销；页面继续留给用户。不会读取日常浏览器的登录资料。由 0.2 升级时，以前填过备注的账号照常可用（显示备注、没有头像）；想换成昵称与头像，重新登录一次再移除旧的那条。

## 开发与验证

```bash
npm ci
npm run check
npm run test:coverage
node scripts/check-host.mjs /本机路径/auto-motion
# 片场源码需先构建命令行与客户端，下面会启动隔离的 Electron 测试实例
node scripts/check-desktop.mjs /本机路径/auto-motion
```

插件的表单流程测试使用临时 Chrome 和本机模拟页面（仅开发测试需要 Chrome），覆盖上传、填表、发布按钮保护、账号隔离与 UI 选择；连接测试验证只使用客户端临时连接。桌面联调运行真实插件和 Electron，使用模拟小红书页面验证视频、封面、文案全部填入，返回项目再打开仍保留用户修改。配套片场的 `apps/desktop/e2e/station-browser.spec.mjs` 另验证会话隔离、连接撤销、文件边界和退出时没有主进程异常。

Node 覆盖率门槛 80%；在网页里执行的 `src/page-scripts.ts` 由真实 Chromium 测试验证。修改后运行 `npm run build` 并提交产物；CI 会核对构建一致性。真实小红书账号登录及真实素材上传仍需验收，网站 DOM 更新可能需要调整选择器。
